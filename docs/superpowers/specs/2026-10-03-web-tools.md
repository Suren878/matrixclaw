# Web tools: search and fetch, no research jobs (2026-10-03)

Phase C item 3 of the audit cleanup (`audit/providers-tools.md` item 3, area
verdict point 3; items 4 and 24 already landed).

## Current shape

- `internal/webresearch` (2,095 lines): an `Engine` with its own async jobs
  (pending/running, heartbeat, stale requeue, retry limit, 30-day cleanup,
  `Start` loop in the daemon), a `Browser` fallback interface, and a
  `DeterministicSummarizer` whose "facts" are title+snippet or a rating regex.
  It persists through `internal/work` (618 lines): tables `work_jobs`,
  `work_artifacts`, `work_facts` in the main SQLite file (`bootstrap.DBPath`,
  opened a second time by `work.NewSQLiteStore`), raw pages as files under
  `<state>/web-research/`. Nothing else uses `internal/work` (core's subagent
  mirror is gone).
- `internal/webtools`: `web_search` (DuckDuckGo/Tavily/Serper/SearXNG, fine),
  `web_fetch` (always routed through the engine; returns only diagnostics and
  artifact IDs, never page text; its non-engine path is dead), three research
  tools `web_research`, `web_research_ask`, `web_research_status` (the model
  must poll status; it cannot `await` these jobs), and `WebService`, which only
  forwards to the engine.
- `internal/daemoncmd/web_research.go`: converts between identical types
  (`WebSearchResult`/`SearchResult`, `WebFetchedPage`/`FetchedPage`,
  `setup.WebSearchConfig`/`WebSearchProviderConfig`) and builds placeholder
  browsers with setup hints.
- `internal/mcp/browser.go` + `modules/mcp.Module.Browser()`: a browser client
  for the fallback, which drives the shared MCP browser outside the model's
  approvals (navigate needs approval when the model calls it).
- Permissions: `tools.Call.Guarded` and `permission.Guard` exist only so a
  guarded research call skips the browser fallback; `permissionTool` maps the
  research tools onto `web_fetch` rules; the redirect recheck travels through a
  context value (`webresearch.WithURLCheck`).
- Prompt: `WebResearchGuidance` steers the model to `web_research` and calls
  `web_search`/`web_fetch` "legacy".
- Clients: terminal (`ui/surface/chat/generic.go`,
  `chat/runtime/app_layout_views.go`) and Telegram (`run_tools.go`) have cases
  for the three research tools. iOS has none. Setup has no research keys.

## Target shape

One package, `internal/webtools`, two model-facing tools.

```go
// web.go
func NewSearchTool(config func() (SearchConfig, error)) tools.Executor
func NewFetchTool() tools.Executor
// search.go: providers as today (RunWebSearch becomes unexported search()).
// fetch.go: fetchPage(ctx, rawURL, recheck) (page, error); HTML -> markdown.
// safety.go: validatePublicURL, dialPublicAddress (moved from webresearch).
// permission_subject.go: subject = host, unchanged.
```

- **web_search** `{query, limit}`: unchanged behaviour and output.
  `WebSearchProviderConfig` is renamed `SearchConfig`; the daemon keeps its
  small closure from `setup.WebSearchConfig` (webtools cannot import setup:
  setup -> gemini, whose schema test registers the web tools).
- **web_fetch** `{url}`: GET through the SSRF-safe transport (public-address
  dialer, no proxy, every redirect re-validated and rechecked against the call's
  permission rules via a per-call `CheckRedirect` closure over `call.Recheck`;
  no context value). The body (up to 5 MB) is decoded by its charset
  (`x/net/html/charset`, x/text is already a direct dependency). HTML becomes
  markdown with the existing extractor; `text/*`, JSON and XML pass through;
  other types fail with "web_fetch reads text pages; <url> is <type>". The
  result is
  `"# <title>\n<final url>\n\n<markdown>"`. No length parameter: core's
  `keepLargeOutput` already writes any result above 8k tokens to
  `<session>/tool-output/<hash>.txt` and leaves head+tail with "the full output
  is in <path> (read it with offset and limit, or grep it)". That is exactly the
  bash behaviour the task asks for, so web_fetch does not re-implement it.
  `task` and `max_length` are dropped from the schema (model-facing input, no
  alias). Metadata is dropped (no client reads it).
- **JS-only pages**: no automatic browser fallback. When an HTML page yields
  under ~200 characters of text and has `<script>` elements, the result ends
  with "The page returned almost no text; it is likely rendered by JavaScript.
  If browser tools are available, open it with them." Browser tools are MCP
  tools under the model's normal approvals and `mcp` rules, so web_fetch never
  drives a browser itself and its URL guard cannot be bypassed through one.
  This deletes `mcp/browser.go`, `Module.Browser()` and the hint placeholders.
- **Deep research**: the model searches and fetches itself, or delegates to
  `agent{readonly:true}` children (they get both tools, run in parallel, and
  background ones are awaited with `await`). `WebResearchGuidance` becomes
  `WebGuidance` (shown when `web_fetch` is registered):
  search then fetch the most relevant results and cite URLs; fetch a named page
  directly; a long page comes back as an excerpt plus a file path, read that
  file instead of fetching again; use browser tools to interact with a page or
  when web_fetch says it needs JavaScript; delegate broad multi-source research
  to readonly agents; keep simple lookups to one search.
- **Permissions**: `permissionTool` loses the research case; `tools.Call.Guarded`
  and `permission.Guard` go (no reader left). `/permissions` usage text drops
  the research sentence part ("web_fetch rules cover every URL web_fetch
  fetches, redirects included").

## Data

- `store.applyCanonicalSchema` gets `dropWorkTables`: `DROP TABLE IF EXISTS`
  `work_facts`, `work_artifacts`, `work_jobs` (children first; indexes go with
  them), next to `dropPlanningTables`. Same DB file, so no second open remains.

  (`os.RemoveAll`, logged on error). Both are phase-D removable.
- Persisted transcripts with old `web_research*` calls still load; clients show
  them through their generic tool rendering ("Web research", raw params).

## Contract changes

Tools `web_research`, `web_research_ask`, `web_research_status` disappear;
`web_fetch` input loses `task`/`max_length` and its result becomes page text.
No HTTP/JSON API shape changes. Clients: remove the research cases in the three
Go files above (minimal edits, C7 is reworking terminal presentation); drop
`task`/`max_length` from terminal's `web_fetch` param display. iOS: nothing.

## Risks and tests

- SSRF: keep and port `TestWebFetchRedirectPolicyRejectsPrivateTarget`,
  `url_safety_test`, and the redirect-recheck test (now through the closure);
  add an executor test that `127.0.0.1`/`169.254.169.254` fail without any
  network call.
- Output: `httptest` cannot be used directly (loopback is blocked), so tests
  call the fetch with an injected dialer/transport: HTML -> markdown with title
  and final URL, charset (windows-1251) decoding, non-text refusal, JS-only note,
  non-2xx error. Overflow-to-file is core's, already tested in core.
- Migration: store test opens a DB that has the three work tables with rows and
  checks they are gone after open (twice, idempotent).
- Permissions: port `TestWebFetchRulesCoverEveryURLFetch` to web_fetch redirects
  only; drop the Guarded assertions.
- Model behaviour change (no research tool, no facts): mitigated by guidance and
  readonly agents; listed in the changelog notes.

## As built

- Commits: design; `refactor(web)!` (research system, work store, browser
  client, `Call.Guarded` removed; `permission.Guard` became the internal
  `guardRule`, which bash ask rules still use); `feat(web)` (extraction);
  `chore(store)` (tables and files); docs.
- Extraction uses `codeberg.org/readeck/go-readability/v2` (the maintained
  fork of go-shiori/go-readability, which is archived) and
  `JohannesKaufmann/html-to-markdown/v2` with the table and strikethrough
  plugins. When readability yields under 250 characters, the whole body is
  converted with nav/header/footer/aside/form/button/svg removed. Links resolve
  against the final page URL. Readability is capped at 50,000 elements.
- Caps: 5 MB downloaded, 400,000 characters returned (with a "page is longer"
  note); core's 8k-token overflow file does the rest.
- JS-only note: at least one `<script>`, under 200 visible characters (script,
  style, noscript and template excluded), and a `<noscript>` or two or more
  scripts. Found text is always returned with it.
- The prompt guidance also gained `turn.ToolUse` gating (it was shown even to
  turns without tools).
- `<data dir>/web-research` is removed at daemon start only when `Lstat` says
  it is a real directory; `RemoveAll` does not follow links inside it, and the
  removal is logged with the file count.
- Fixtures in `internal/webtools/testdata`: a Wikinews article (CC BY 2.5),
  the go.dev getting-started tutorial (CC BY 4.0) and the Excalidraw app shell
  (MIT), each with its source in a leading comment.
- `go.mod`: the two libraries bring go-shiori/dom, JohannesKaufmann/dom,
  cascadia, chardet and dateparse, and bump goldmark 1.7.17 -> 1.8.2 and
  go-isatty 0.0.20 -> 0.0.22 (indirect).
